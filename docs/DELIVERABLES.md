## Measurable improvements

For the hackathon judging criteria:

| Criterion | How ArmTune Serve addresses it |
|-----------|-------------------------------|
| **Model size** | Quantization comparison (Q2_K through F16) — measures disk + RAM reduction |
| **Model quality** | Structured JSON quality scorer — ensures output quality isn't sacrificed for speed |
| **Inference speed** | TTFT, decode tokens/sec measurement across configs |
| **Inference-server throughput** | Concurrency sweep + aggregate tokens/sec |
| **Developer experience** | Single `armtune` CLI, automated profiling, YAML profiles, ready-to-run GitHub Actions |
| **Arm-specific optimization** | **Arm Performix** hardware counter profiling (IPC, cache misses, branch prediction, memory bandwidth) — provides Arm-native evidence |

## What's NOT delivered (v1 scope boundaries)

- No custom inference engine or kernels
- No model training, fine-tuning, or RLHF
- No custom quantization algorithms
- No distributed or multi-node inference
- No Kubernetes deployment
- No production auth, billing, or API gateway
- No GPU optimization (planned for v2)
